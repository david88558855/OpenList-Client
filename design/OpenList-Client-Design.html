01 — Overview

一个入口，接管所有挂载

OpenList 把几十种存储抽象成同一棵目录树。客户端不去重复造轮子，而是把这棵树做得「像本地硬盘一样顺手」：浏览、搜索、预览、传输、分享，全部围绕真实 API 展开。

统一命名空间

侧栏按挂载点分组，跨存储搜索一次命中。路径、权限、可用性全部来自服务端 /api/fs/list，不做本地假数据。

传输即主角

下载 / 上传 / 离线下载统一进任务中心，支持并发、限速、断点续传与后台常驻。Windows 托盘与 Android 前台服务保持同一套语义。

凭据不出设备

Token 存系统钥匙串 / Keystore，多服务器配置本地隔离。客户端只与你填写的地址通信，默认拒绝明文 HTTP（可手动放行内网）。

06 — API Mapping

每个界面都落在真实接口上

以下端点均来自 OpenList 仓库 server/router.go，客户端不依赖网页端内部状态。请求统一带 Authorization，并处理 401 续签与 429 退避。

鉴权

POST /api/auth/login 返回 token，后续请求头 Authorization: <token>。支持 2FA 与 LDAP 登录。

下载与播放

列表项的 sign 拼出 /d/<path>?sign= 直链；/p/ 走代理。播放器依赖服务端 Range 支持。

错误语义

业务错误统一 {code,message}。401 回登录、403 显示权限、404 提示路径失效、429 按 Retry-After 退避。

验收条款：08 验收标准「托盘」行
问题描述Windows 环境下启动便携版后，通知区域未出现 OpenList 托盘小图标（或显示为空白 / 系统默认占位图标）。由此：空闲 / 传输中 / 有失败任务 / 已暂停离线四种图标状态全部不可见，传输完成通知缺少托盘载体，用户关闭窗口后无法把主界面调回来，只能靠任务管理器结束进程。
复现环境：Windows 10 / 11 x64，便携版 zip 解压运行。
影响范围影响 Windows 端全部用户，属入口级缺陷：
① 左键双击「显示主界面」不可用；
② 右键菜单「显示主界面 / 退出」不可达；
③ 「关闭窗口 = 收进托盘」变为「关闭即失联」；
④ 直接阻塞 08 验收标准「托盘」全项；
⑤ 与 K-02 叠加时退出完全不可靠。
Android 端不受影响。
处理方向：① 确认 app_icon.ico 已加入 runner 资源并在打包中输出（打印 Shell_NotifyIcon 返回值）；② 托盘初始化必须在主 isolate ready 之后、窗口隐藏之前执行 NIM_ADD，失败需重试；③ 校验图标尺寸与 DPI（16/20/32/40/48 多尺寸 + 高 DPI 变体）避免回落到空白；④ 进程 / 资源句柄释放后补 NIM_MODIFY 重建图标，防止 Explorer 重启后图标丢失。

验收条款：08 验收标准「托盘」行（仅「退出」结束进程）
问题描述点击托盘菜单「退出」后进程并未立即结束，界面或后台进程仍然存在，需要重复点击多次（或反复触发）才真正退出。与 W9 约定「仅托盘『退出』结束进程」不一致。
复现环境：Windows 10 / 11 x64，便携版 zip；托盘菜单 → 退出。
影响范围① 退出路径不可靠，用户无法一次退出，只能强杀进程；
② 残留进程继续占用单实例锁，下一次启动被判为第二实例而被拦在最前，表现为「点了没反应」；
③ 便携版 userdata/prefs.json 可能在偏好 flush 完成前被截断，丢失最后一次设置；
④ 托盘槽位残留重复图标，进一步掩盖 K-01 的排查；
⑤ 阻塞 08 验收标准「托盘」与「安全」两项。
处理方向：① 统一退出入口，确认「退出」调用链没有被 window_manager 的 preventClose / 关闭拦截吃掉（关闭与退出必须是两条不同分支：关闭 = hide 到托盘，退出 = 真正退出）；② 退出前按序 await：flush prefs → 释放单实例锁 → NIM_DELETE 移除托盘图标 → exit(0)；③ 保证退出逻辑在主 isolate 只执行一次，避免重试导致的多次确认；④ 补一条退出后的自测：进程列表中无残留 OpenList 进程。
